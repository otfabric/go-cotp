# Testing

All tests are in the root package and need no network beyond loopback, no Docker and no hardware. There are no prerequisite-gated tests, so there is no `*_REQUIRE_*` variable.

## Tiers

| Tier | Command | What it runs |
|---|---|---|
| Unit and service | `make test` | Codec, negotiation, handshake, TSDU and open-state tests |
| Short | `make test-short` | The same with `-short` (no test currently shortens itself) |
| Race | `make test-race` | The same with the race detector |
| Coverage | `make coverage-check`, `make coverage-pkg-check` | Fails below 90% in total, below 92% for the package |
| Chaos | `go test -race -run Chaos .` | `TestDuplex_Chaos*`; `COTP_CHAOS_SEEDS` raises the seed count (default 4 and 8) |
| Fuzz | `make fuzz` | Every `Fuzz*` target for `FUZZTIME` (default 5s) |
| Selected fuzz | `make fuzz-decode`, `make fuzz-parse` | `FuzzDecode`; the two parameter parsers |
| Benchmarks | `make bench` | `bench_test.go` |
| Cross-compile | `make cross` | Build only, without cgo; no test runs on these platforms |
| 32-bit | `GOARCH=386 go test ./...` on linux/amd64 | The whole suite as a 32-bit binary, without the race detector (it does not exist for `386`); nightly. `GOOS=linux GOARCH=386 go vet ./...` checks that the test package compiles for it on any host |
| Everything local | `make check` | Formats and tidies, then vet, staticcheck, golangci-lint, govulncheck, tests, race, coverage gates |

`make lint`, `make lint-ci` and `make vuln` need `staticcheck`, `golangci-lint` and `govulncheck` on `PATH`.

CI (`.github/workflows/ci.yml`) runs the shared go-ci workflow on Go 1.26 and 1.27 with the race detector, coverage minimum 90, govulncheck and 10 seconds per fuzz target, a `package-coverage` job (`make coverage-pkg-check`), and a `closure-gates` job: module verify, staticcheck and the fuzz seed corpus.

`.github/workflows/nightly.yml` runs every Fuzz target for 5 minutes, the chaos tests with 200 seeds under the race detector, and the whole suite as a 32-bit binary (`GOARCH=386`). A failing fuzz input is uploaded as an artifact. `make fuzz` runs `scripts/fuzz.sh`, which treats a target that fails only with "context deadline exceeded" at the end of `-fuzztime` and wrote no failing input as a pass: Go before 1.28 reports that spuriously ([golang/go#75804](https://github.com/golang/go/issues/75804)). Remove the workaround once the minimum Go version is 1.28.

## Determinism

No test sleeps to let a call block on the stream. A test that needs to know a call is blocked there uses one of three things:

- `testing/synctest` with `net.Pipe`: inside the bubble `synctest.Wait` returns once every goroutine is blocked, and contexts and stream deadlines run on the bubble's clock. A bubble also fails the test when a goroutine started in it is still blocked at the end.
- `scriptConn` (`script_conn_test.go`): a `net.Conn` that plays a script and reports when its reader has consumed it and waits for more.
- `readWatch` (`tcp_test.go`): a wrapper around a real socket, where a bubble cannot be used, that reports when a `Read` is entered.

The `time.Sleep` calls that remain: the jitter of the chaos tests and the pacing of the write and read loops of `TestDuplex_WriteKeepsReadDeadline` and `TestDuplex_ReadKeepsWriteDeadline` (`duplex_test.go`), a peer that never answers (`tcp_test.go`), and, in the unit tests of `directionDeadline` (`deadline_test.go`), one loop that polls for the cancellation callback and one microsecond yield to it.

`TestReadTSDU_PendingReassemblyBudget` reads the process-wide memory statistics, so it is not parallel. Its default-limit case (four million packets) is left out of a test binary built with `-race`, where it would take most of a minute; the plain test run and the 32-bit run execute it, and the 64 KiB case runs everywhere.

## Lifecycle contract matrix

The matrix of otfabric/engineering `standards/lifecycle.md`, for `*Conn`, the one long-lived type (built by `Connect` and `Accept`). go-cotp starts no goroutine, so there is no leak helper; the tests named `TestLeak_*` check that blocked calls return.

| Row | Applies | Tests, or the reason it does not apply |
|---|---|---|
| L1 Close twice | yes | `TestConn_LocalCloseReturnsErrClosedNotDisconnected`, `TestConn_ReferenceReleasedExactlyOnce`, `TestConn_TerminalCauseCannotBeOverwritten`. The documented value is `ErrClosed`, or the first terminal cause; never nil |
| L2 Two goroutines call Close | yes | `TestLifecycle_ConcurrentClose`: every call returns `ErrClosed`, the stream is closed once, the reference is released once |
| L3 Close during a blocked read | yes | `TestTSDU_LocalCloseUnblocksRead`, `TestTSDU_LocalCloseMidReassembly`, `TestLeak_CloseUnblocksReadTSDU`: the read returns `ErrClosed` |
| L4 Close during a write | yes | `TestLifecycle_CloseDuringWrite` (the write returns `ErrClosed`; the stream ends inside the interrupted segment and nothing follows it), `TestLeak_CloseUnblocksWriteTSDU` |
| L5 Close during the handshake | as the context ending | No `Conn` exists during the handshake, so there is nothing to close: the row is the context of `Connect` or `Accept` ending. `TestLifecycle_HandshakeContextEnds` (`ErrClosed` with the context's error, reference released, stream closed, for a cancellation and for a deadline), `TestConnect_ContextCancelAfterIOStartsClosesStream`, `TestConnect_ContextCanceledBeforeIO`, `TestTCP_CancelUnblocksConnect`; a peer that closes instead: `TestLeak_CloseUnblocksConnect`, `TestLeak_CloseUnblocksAccept` |
| L6 Cancel a pending request | n/a | No request and response correlation. The analogue, an operation cancelled before any octet moved leaves the connection usable, is covered by `TestTSDU_IdleContextTimeoutKeepsOpen`, `TestLeak_TimeoutGoroutineExits`, `TestDuplex_CancelInterruptsOnlyItsDirection` and `TestDuplex_QueuedWriterHonoursContext`. Over TLS it holds for reads (`TestTSDU_IdleReadTimeoutOverTLSKeepsOpen`); a write timeout over TLS ends the connection instead (`TestTSDU_WriteTimeoutOverTLSEndsConnection`, [ERRORS.md](ERRORS.md#connection-sentinels)) |
| L7 Response after a timeout | n/a | No pending requests |
| L8 Response after reconnect | n/a | No reconnect |
| L9 Callback calls a public method | n/a | `OnConnect` runs before a `Conn` exists and receives copies: it has nothing to call back into |
| L10 Callback calls Close | n/a | As L9: there is no `Conn` to close yet |
| L11 Slow callback | yes | `TestLifecycle_SlowOnConnectStallsOnlyItsHandshake` (another connection is established and used while the callback runs), `TestLeak_CallbackBlockedPeerCloses` |
| L12 Queue at capacity | n/a | No queue. Callers waiting for their direction honour their context: `TestOpLock_HonoursContext`, `TestDuplex_QueuedWriterHonoursContext` |
| L13 Concurrent sessions | yes | Connections share only the reference allocator: `TestLifecycle_SlowOnConnectStallsOnlyItsHandshake` (two connections, distinct references, data stays on its connection), `TestReferenceAllocator`; many senders on one connection: `TestDuplex_ParallelSendersOneReader` |
| L14 Failure during construction | yes | `TestLifecycle_FailedConnectReleasesEverything` (every failing path of `Connect`: no `Conn`, reference released, stream closed), `TestHandshake_ConnectionTimeoutIsDisconnect`, `TestConnect_ConfigFailureClosesStream`, `TestAccept_ConfigFailureClosesStream`, `TestAccept_FailureReleasesReference`, `FuzzAcceptHandshake` |
| L15 Shutdown | n/a | No graceful shutdown: a TP0 connection ends by closing the stream |
| L16 Close racing reconnect | n/a | No reconnect |

## Coverage policy

The minimum is 90% of statements of the root package. It is set in `Makefile` (`COVERAGE_MIN`) and `.github/workflows/ci.yml` (`coverage-min`). The per-package floor is 92% (`COVER_PKG_MIN`), just below the 93.3% measured when it was set. Nothing is excluded: the module has one package.

## Fuzz invariants

The decoder targets (`FuzzDecode`, `FuzzDecodeCR` to `FuzzDecodeRJ`, `FuzzMarshalDecodeRoundTrip`) share one oracle, `assertDecodeInvariants` in `codec_invariants_test.go`: a failure matches a sentinel of [ERRORS.md](ERRORS.md) and returns no value; a success exposes only clipped sub-slices of the input, encodes again, decodes from that encoding to a deeply equal value, and, for the types with one encoding, gives back the octets that were read; a DC, ER, AK, EA or RJ that decodes ends with its header. `FuzzMarshalParameters` asserts that every TPDU an encoder writes decodes to the same parameters. `FuzzParseVariablePart` and `FuzzParseCRCCVariablePart` assert the same for the parameter parsers, and `FuzzLooksLikeDoesNotPanic` that the classification helpers agree with `PeekType`. `TestDecode_EveryPrefixOfValidTPDUs` walks every prefix of the golden fixtures in `testdata/unit/` and of TPDUs with a variable part.

## Fuzz regressions

`go test -fuzz` writes a failing input to `testdata/fuzz/<Target>/`. Fix the bug, commit that file, and it runs as a seed in every `go test` from then on. Do not delete a corpus file to make a test pass.

## When CI runs

| Event | Workflow | What runs |
|---|---|---|
| Pull request | `pr.yml` | `docs.yml` (docsync, otfabric-policy) always; `ci.yml` unless every changed file is documentation; then `OT Fabric Required Checks` |
| Push to a branch | none | nothing; dispatch `ci.yml` to test a branch without a pull request |
| Push to `main` | `docs.yml` | the light checks; the merged commit was tested as the pull request's merge commit |
| Schedule | `nightly.yml` | the scheduled runs, on `main` |
| Release | `release.yml` | the release workflow tests the release commit again |

Documentation means an added or modified `*.md` file outside `.github/`, `testdata/` and `vendor/`, other than `AGENTS.md` and `CLAUDE.md`. A deleted or renamed document, or any other file, runs everything. `OT Fabric Required Checks` fails unless every job that applies succeeded; its summary lists them.
